## 2026-08-08 - [Clear search input overlap & Accessibility]
**Learning:** When adding inline interactive action buttons (like a "Clear Search" button) inside a text input field, dynamic horizontal padding (e.g. dynamic Tailwind classes like `pr-10` vs `pr-4`) must be strictly applied to prevent input text or native interactive focus boundaries from overlapping or colliding under screen readers and keyboard navigation. Additionally, including an explicit hidden accessibility label (`sr-only`) ensures semantic clarity for assistive devices when visually-focused elements lack physical text content.
**Action:** Always wrap standard inputs with a relative container when adding inline accessories, and scale sibling padding conditionally depending on the presence of absolute visual elements to avoid overlapping and preserve pristine keyboard accessibility.
